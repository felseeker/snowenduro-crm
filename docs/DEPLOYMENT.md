# Размещение SnowEnduro CRM

## Что показал существующий проект

Рабочая CRM использует бессерверную схему: API Gateway принимает HTTP-запросы, Cloud Functions выполняют серверную логику, а YDB в режиме Serverless хранит записи. Object Storage служит для файлов. Для публикации также нужны права сервисных аккаунтов, HTTPS/DNS и резервное копирование.

Это только архитектурный ориентир. В новую CRM не переносятся данные, ключи, таблицы, бакеты, функции или учетные записи старой системы.

## Целевая схема SnowEnduro

- Все ресурсы новой CRM — только в отдельном каталоге snowenduro-crm.
- Один API Gateway и одна Cloud Function для API и проверки доступа; отдельные версии одной и той же функции не копируются.
- YDB Serverless хранит заявки, учетную запись администратора, сессии, каталог и очередь уведомлений.
- Object Storage используется только для фотографий каталога. Записи клиентов и документы с персональными данными там не размещаются.
- Публичный сайт остаётся на GitHub Pages. DNS сайта не меняется.
- Персональные данные доступны только через API после серверной проверки сессии.

## Текущее состояние

Локальная версия в этом репозитории пока использует Node.js и SQLite. Для бессерверного размещения её серверную часть нужно адаптировать под Cloud Functions и YDB. До этого публичный backend не готов, а GitHub Pages показывает только статическую часть.

## Ограничение расходов

- Не создавать VM, Docker-инфраструктуру или платные ресурсы.
- Не использовать ресурсы старой CRM.
- Free tier Yandex Cloud общий для платежного аккаунта: нагрузка всех его облаков расходует один и тот же месячный лимит. Если лимита не хватит, сервисы могут начислить плату.
- Перед созданием ресурсов проверить доступный остаток лимитов и остановиться до любых возможных платных действий, если нулевой расход нельзя гарантировать.
- Эта инструкция не создаёт ресурсы и не меняет настройки облака.

Официальные условия free tier: https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier
