# Размещение CRM в отдельном каталоге Yandex Cloud

## Схема

- Один Linux-сервер в регионе `ru-central1` в каталоге `snowenduro-crm`.
- Node.js 24 запускает CRM и API; SQLite и фотографии лежат на загрузочном диске этого сервера.
- Caddy на том же сервере принимает HTTPS и проксирует запросы в Node.js.
- Публичный сайт остаётся на GitHub Pages. Для CRM используется `admin.snowenduro.ru`.
- Docker, Supabase, отдельный сервер базы данных и Kubernetes не нужны.

## Подготовленные файлы

- `deploy/snowenduro-crm.service` — запуск приложения через systemd.
- `deploy/Caddyfile` — HTTPS для `admin.snowenduro.ru` и проксирование на локальный Node.js.

## Что нужно настроить перед запуском

1. Создать одну виртуальную машину в новом каталоге и подключить к ней диск.
2. Разрешить входящие TCP-порты 80 и 443; SSH ограничить своим адресом.
3. Добавить отдельную DNS-запись `admin.snowenduro.ru`, не меняя записи публичного сайта.
4. Установить Node.js 24 и Caddy, затем собрать приложение и включить systemd-службу.
5. Создать `/etc/snowenduro-crm.env` с закрытыми правами доступа. Перед первым удалённым входом обязательно задать случайный `SETUP_TOKEN`; после создания администратора удалить его и перезапустить службу.
6. Проверить резервное копирование SQLite-базы и `uploads` перед приёмом реальных заявок.

Создание каталога Yandex Cloud не запускает платные ресурсы. Виртуальная машина и публичный IP тарифицируются отдельно; эта конфигурация подготовлена, но сама машина и DNS-запись не создаются автоматически.
